# 2026-07-31 NGMEMBERS Development Log

## Work Summary

PC에서 회원 카드의 회원번호를 드래그해 복사하려 할 때 카드가 펼쳐지거나 접히는 충돌을 해결했다. 카드 요약의 기존 클릭 동작은 유지하면서 회원번호만 독립적으로 선택할 수 있게 했다.

## Work Completed

- 카드 요약을 텍스트 선택이 가능한 컨테이너로 변경했다.
- 회원번호에 텍스트 선택 커서와 `user-select: text`를 적용했다.
- 회원번호에서 발생한 클릭이 카드 토글로 전달되지 않도록 이벤트를 분리했다.
- 카드 요약의 Enter·Space 키보드 토글과 포커스 표시를 유지했다.
- TypeScript 프로덕션 빌드와 기존 데이터 계층 테스트로 변경의 정적 안정성을 검증했다.

## Decisions

별도의 복사 버튼을 추가하면 화면과 조작 요소가 복잡해지므로, PC에서 익숙한 드래그 선택과 복사 방식을 지원하기로 했다. 카드의 나머지 영역은 기존처럼 클릭해 펼치고 접을 수 있게 유지했다.

## Current Status

회원번호 선택과 카드 토글의 이벤트 경계를 코드에 반영했고 프로덕션 빌드는 통과했다. 로컬 앱은 인증 세션이 없어 실제 회원 카드의 드래그 상호작용까지 자동 검증하지 못했다. 기존 Phase 4 테스트에는 이번 변경과 무관한 검색 문구 순서 불일치 1건이 남아 있다.

## Next Steps

- 로그인된 개발 환경에서 PC 드래그 선택을 최종 확인한다.
- 실제 배포는 이번 작업 범위에 포함하지 않았다.

## Work Summary - 앱 전환 후 30분 작업 상태 복원

회사 사이트와 NGMEMBERS를 오가는 실제 업무 중 검색 위치와 편집 화면이 초기화되는 문제를 수정했다. 앱 전체를 장기간 기억하지 않고, 마지막 작업으로부터 30분 동안 필요한 화면 위치만 복원하도록 구성했다.

## Work Completed - 앱 전환 후 30분 작업 상태 복원

- 같은 사용자의 Supabase 토큰 갱신 이벤트에서는 권한 확인 화면으로 전환하지 않도록 인증 상태 처리를 수정했다.
- 앱 복귀 시 회원 데이터가 새로고침되어도 열린 편집 폼의 입력값이 원본 데이터로 덮어써지지 않도록 초기화 조건을 회원 ID 변경으로 제한했다.
- 현재 필터, 열린 회원 ID, 편집 중인 회원 ID, 스크롤 위치를 버전이 있는 `localStorage` 작업 컨텍스트로 저장했다.
- 작업 컨텍스트는 마지막 저장 후 30분이 지나면 복원하지 않고 폐기하도록 했다.
- 로그아웃 시 작업 컨텍스트를 즉시 삭제하도록 했다.
- 기존 Phase 4 검색 문구 테스트를 실제 문구 순서와 맞추고, 정상·만료·손상 작업 컨텍스트 회귀 테스트를 추가했다.
- Phase 3 안전 검사가 최소 UI 컨텍스트만 명시적으로 허용하고 회원 row 필드는 계속 차단하도록 검증 계약과 구현 보고서를 갱신했다.

## Decisions - 앱 전환 후 30분 작업 상태 복원

전체 회원 정보나 전화번호·CPF·메모 같은 민감한 입력값은 브라우저 저장소에 추가로 보관하지 않는다. 서버의 회원 ID와 화면 위치만 저장해 최신 회원 데이터는 Supabase에서 다시 읽도록 했다. 일반적인 탭·앱 전환에서는 React 편집 상태를 유지하고, 모바일 운영체제가 페이지를 폐기한 경우에는 같은 회원과 편집 화면까지 복원하는 경계로 결정했다.

## Current Status - 앱 전환 후 30분 작업 상태 복원

프로덕션 빌드, Phase 3 테스트 8개, Phase 4 테스트 9개가 모두 통과했다. 로컬 주소에는 로그인 세션이 없어 실제 회원 데이터로 브라우저 전환 복원까지는 자동 검증하지 못했다.
